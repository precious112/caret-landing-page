Figma Make alternatives, and Figma Make vs Lovable

Figma Make turns a prompt or a design into a working front end. The tools people compare it with all do something similar, and differ in the part that matters a month later: where the code lives and whether you can keep working on it.

Updated 6 October 2026 · 7 min read · Caret is not affiliated with any product named here. Details checked on the date above.

What Figma Make is

Figma announced Make at Config in May 2025 and made it generally available on 24 July 2025. It is a prompt-to-app tool inside Figma: describe a screen, or start from a design or image, and it builds a working prototype. Full use needs a Full seat, and each prompt spends AI credits (credit FAQ).

You can download Make’s code as a zip or push it to GitHub. The push is one-way: changes made on the GitHub side are overwritten by the next push from Make. If you plan to keep working on the code outside Make, that one detail matters most.

Lovable

The most common comparison. Lovable builds full-stack apps from chat, including a database and deploys. Its GitHub integration syncs both ways on one branch: changes in Lovable are pushed to GitHub, and changes pushed to that branch come back into Lovable. The code is stored and managed on Lovable’s platform.

v0

Vercel’s v0 generates Next.js with Tailwind and shadcn/ui, can start from a screenshot or Figma file, and can open a pull request for review. There is a free tier with a daily message limit.

Bolt

Bolt builds apps and websites by chat and handles hosting and databases for you.

Google Stitch

A Google Labs experiment that turns prompts and images into UI designs and front-end code, which you can paste into Figma.

Magic Patterns

Magic Patterns describes itself as an AI design tool that helps product teams go from idea to production by generating UI.

Short version: Make fits best when the design already lives in Figma, and Lovable when you want a full-stack app and are starting from nothing. Both charge per use through credits, so a long back-and-forth costs more than the plan price suggests.

If you already have an app

Every tool above is strongest at the start of a project. They generate a new codebase, or a new prototype, and work best while they own it. The harder case is a product that already exists, with its own framework, components and business logic, where you want to change how it looks without handing it to another platform.

That is the case Caret is built for. It is a free, open-source desktop app that keeps the design inside your existing repo, as real React in a .caret/ folder beside your app:

  • you design on a live canvas, by clicking and editing, or by marking a region and describing it;
  • every change is a file in git, so nothing is overwritten by a push from somewhere else;
  • when you are ready, an agent makes your app match, in whatever framework it already uses, and keeps your app’s data and API wiring as it was.

Nothing is hosted. There is no credit meter in Caret itself: you connect a model you already pay for, such as a ChatGPT or GitHub Copilot plan, or an API key.

Questions

  • Is there a free alternative to Figma Make?

    Google Stitch is free, with monthly generation limits, while it is a Google Labs experiment, v0 has a free tier, and Caret is free and open source, though you supply the AI model.

  • Can I export code from Figma Make?

    Yes, as a zip or by pushing to GitHub. The GitHub push is one-way.

  • Which one gives me the most control over the code?

    The ones where the code lives in your own repo from the start: v0’s pull requests, or Caret, which never leaves your repo at all.
